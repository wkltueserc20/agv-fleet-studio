# Rust RCS Lab — 本機介接與車隊流程模擬

同一台 Windows 電腦執行七個獨立 Rust 程序：外部介接入口、WCS、RCS、ECS 與三台模擬 AGV，以 HTTP/JSON 協調作業。

| 角色 | 網址 | 用途 |
|---|---|---|
| 外部介接入口（integration-service） | http://127.0.0.1:8210 | 整張作業交 WCS；單項 MOVE 交 RCS |
| WCS | http://127.0.0.1:8215 | 整張作業步驟、設備等待與用車協調 |
| ECS | http://127.0.0.1:8216 | 設備信號模擬與取放料握手 |
| RCS | http://127.0.0.1:8211 | 任務入列、選車、三車併行派發、取消、保存狀態與事件 |
| CT-SIM-01 | http://127.0.0.1:8212 | 第一台車的獨立車端程序與操作頁 |
| CT-SIM-02 | http://127.0.0.1:8213 | 第二台車的獨立車端程序與操作頁 |
| CT-SIM-03 | http://127.0.0.1:8214 | 第三台車的獨立車端程序與操作頁 |

## 啟動與操作

1. 雙擊 `啟動.cmd`，首次會使用已安裝的 Rust 編譯專案。
2. 在介接服務選「機台 A → 機台 B」，建立任務。
3. 切到 RCS 看任務清單與事件，再切到模擬 AGV 看移動。
4. 可按介接服務的「三車測試：建立 4 張任務」，觀察三車併行與第 4 張排隊。
   任務時間依路徑長度與等待情形而變。RCS 依建立順序，選擇距離取料點最近的空閒車。
5. RCS 的「暫停新任務派發」只暫停派車；AGV 的「暫停模擬走行」暫停車端進度。
6. 雙擊 `停止.cmd` 停止五個程序。

也可以在專案目錄執行 `powershell -NoProfile -File .\start.ps1`。重新編譯前先停止本專案。

## 流程

介接服務 POST /api/tasks → RCS POST /api/tasks → 保存 QUEUED → 派車迴圈 →
AGV POST /api/missions → 每 0.5 秒推進模擬 → RCS POST /api/events → 完成。

每個服務有 GET /health、GET /api/snapshot 與自己的網頁。RCS 與 AGV 另外有
GET /api/state。介接服務不直接保存任務，任務唯一來源是 RCS。

## 查看 API 實際傳了什麼

每個畫面都有「API 中間傳了什麼？」面板，顯示接收端實際捕捉的請求、JSON 回應、
HTTP 狀態、來源／目的服務、任務編號與接收端處理時間。
可依任務篩選，預設顯示下單、派車、控制與車端回報；狀態查詢另外切換查看。
GET 狀態輪詢每個來源／路徑每兩秒取樣；控制與回報不取樣。
各程序保留最近 160 筆控制／回報及 20 筆查詢在記憶體，重啟後清空，不補造過去封包。
GET /api/traces 提供該程序的紀錄，GET /api/snapshot 彙整五個程序的紀錄。
可依車號篩選；派單與回報包含 vehicle_id，任務包含 assigned_vehicle。
請求來源標籤來自本機示範用 X-Lab-Source 標頭，不是正式驗證憑證。

時間顯示統一為台北 UTC+08:00，包含日期與毫秒。每筆 API 有 received_at（完整收到請求）、
response_ready_at（回應內容產生）、responded_at（回應寫入本機 socket；失敗時 null）。
這些時間不表示發送端的開始時間，也不表示遠端已確認收到。
任務 timing 保存派發、接單確認、首次進度、完成、取消或待確認時間，隨任務寫入資料檔。
舊版任務缺少的時間不補造，畫面顯示 —。

畫面另有「目前有哪些 API？」：GET /api/catalog 回傳本機原型目前已實作的 API 清單，
包含介接服務、RCS、AGV 各自的路由與四項共用介面。共 28 種路由定義、58 個服務入口。
格式範例與上方實際傳輸紀錄分開，沒有新增真車控制功能或海康相容介面。

任務範例：

```json
{"request_id":"request-001","from":"A","to":"B"}
```

目前站點包含機台、充電、待命與空閒區；完整清單見 `/api/map` 與下方廠區表。request_id 是建立任務的去重鍵；重送同一鍵回同一張單，
相同鍵但不同路線會拒絕。任務編號由 RCS 產生。車端也避免同一任務重複啟動。

取消：POST /api/cancel/{task_id}。RCS 佇列任務直接取消；執行中的任務交車端確認後回報。
派車開關：RCS POST /api/dispatch，body `{"enabled":false}`。
車端暫停：AGV POST /api/control，body `{"paused":true}`。

## 三車選擇與隔離

- 任務先進先出，每張任務選取料點最近的可用車。距離取自示意百分比座標，不是真實公尺。
- 可用車必須在線、未暫停、無執行中任務、回報佇列已送完，而且 RCS 沒有其他執行中任務占用它。
- 三台皆忙或不可用時保留 QUEUED，空車恢復可用後自動接續。
- RCS 先保存 assigned_vehicle，再將帶 vehicle_id 的任務送至該車連接埠。
- 車端拒絕車號不符的任務；RCS 拒絕車號不符的任務回報。
- 取消執行中任務依 assigned_vehicle 找對應車端，避免停到其他車。
- 各車有自己的進度、去重記錄、暫停狀態及回報佇列；各操作頁只控制自己的車。
- GET /api/vehicles 在介接服務與 RCS 都可用，回傳三台車的即時狀態及離線錯誤。
- 地圖車輛圖示在邊界保留顯示留白，原始座標仍以 API 真值為準。

## 資料與重啟

- 啟動腳本指定的任務與最近 150 筆事件：本專案的 `data/rcs.json`，逐次存檔。
- 直接執行程式而未設定 `RCS_DATA_DIR` 時，才使用工作目錄的 `data/rcs.json`。
- 日誌與程序編號：`run/`。
- RCS 重啟保留排隊任務；先前交付中或執行中的任務標為 INTERRUPTED（待確認），不重派。
- 車端執行進度與待送回報只在記憶體；重啟會遺失，尚無真車復原協定。
- 車端回報在程序存活期間會依序重試。回報未送完前不接下一單。
- 交付結果不明時標為待確認，不自動重送控制命令。
- 整個專案上限 10000 張任務；示範畫面只顯示最新 50 張。

## 範圍

這是本機學習與架構驗證原型，不是正式車隊系統。
不連 ROS、PLC、海康或原有 db_api；未修改原始專案。
模擬位置為示意百分比；使用 Dijkstra 計算合法道路路徑，再逐段插值移動。不是實車定位或車體避碰。電量固定顯示 85%。
五個程序只監聽 127.0.0.1，不供其他電腦連線；未做正式認證、TLS、交管或硬體安全控制。
多車併行包含任務隔離、站點占用、路段與路口預約；尚無車體避碰、硬體安全控制或充電調度。
API 是自家原型格式，尚未相容海康的請求與回應協定。

## 開發與測試

Windows 建議執行 `powershell -NoProfile -File .\build.ps1 -Action test`，
或 `powershell -NoProfile -File .\build.ps1 -Action build`。
編譯輸出及執行檔統一放在本專案的 `target/`；啟動腳本指定本專案 `data/` 儲存任務，
`run/` 儲存日誌與程序記錄，測試資料放在 `run/tests/`，不依賴 AppData。

五程序三車整合測試：先停止本專案，再執行 `python tests/integration.py`。
測試使用獨立資料，驗證三車併行、最近空車、第四張排隊、錯車回報拒絕、指定車取消、
暫停／恢復、離線車跳過、重新連線、API 時間點與紀錄，以及 RCS 重啟復原，不寫入展示資料。
首次建置需從 crates.io 取得 serde / serde_json 與編譯依賴；建置後啟動無需網路。
`RCS_DATA_DIR` 可指定測試資料目錄。

## 站點占用與自動讓位

正常在介接服務建立搬運任務即可；可讓 RCS 選車，也可指定 CT-SIM-01/02/03。
主畫面顯示站點占用、預留、等待原因／開始時間，以及讓位任務與原搬運任務的關係。
已移除建立情境與手動移位的操作流程。內部 `/api/sim/*` 僅保留給回歸測試設定位置，
自動讓位不會呼叫這些 API，也不會直接更改車輛座標。

- 取料站或目的地被另一台空閒車占用時，RCS 自動建立 `kind:YIELD` 的移動任務，
  `parent_task` 指向原搬運任務；一般搬運為 `kind:TRANSPORT`，舊任務預設為搬運。
- 選擇距離占用站最近的可用 P1/P2/P3；排除被占用、被預留、車況過期，或其他未完成任務起終點。
- 同一鎖內保存等待點預留，再優先派發讓位；普通搬運仍依建立順序派發。
- 讓位車走 `/api/missions`，先以 `stage:move` 申請許可，逐步更新位置並經 `/api/events` 回報。
  模擬讓位時間依核准路徑長度而變，沒有搬運任務的取貨或放貨階段。
- 原搬運車留在原地，等讓位任務完成且點位清空，再取得進站預留；重複申請不會重建相同讓位任務。
- 忙碌、暫停、離線、回報未送完、預留待確認的車不強制移走；沒有空等待點時也保持等待。
- 暫停新任務派發時不建立新的讓位任務，已交付車端的任務繼續。
- 取消原搬運任務：尚未交付的讓位取消；已接受的讓位繼續到等待點。
  取消或中斷讓位後，原搬運任務保持等待，不默默重建或忽略異常。

車端在開始前往取料站、離開取料站前，POST /api/entry（pickup / destination）；讓位使用 move。
RCS 背景更新車況，進站鎖內不等待網路。使用最新可用位置、任務階段與持久化預留做互斥判斷；
連線車況超過 5 秒未更新則不放行。完成／取消任務的預留保留到新車況確認最終位置且回報送完，
避免舊位置造成短暫誤放行。離線車保留最後位置；位置未知時不放行。
RCS 重啟保留原搬運、讓位任務的關聯及預留，執行中任務標為 INTERRUPTED，不重派、不自動釋放。
尚無正式復原確認介面，有待確認預留時需人工查核。

目前已包含站點與路網層級的預約，尚未檢查真實車體範圍，亦不會自動解開忙碌車的站點互等。
已加入下述路網與整趟路徑預約；尚非完整車體避碰或硬體安全控制。

回歸驗證：停止本專案並建置後，執行 `python tests/stations.py`（自動讓位）及
`python tests/integration.py`（三車派單、隔離與 API）。兩者都使用獨立測試資料。

## 路網、路徑計算與路段交管

- GET `/api/map`：18 個站點、18 個路徑點（J1–J18），共 41 條道路；J2→J5 為單向，其餘雙向。
- 車輛先依 Dijkstra 最短路徑前往取料站，再取得下一趟送貨路徑；讓位任務同樣沿路網行駛。
  路徑避開已知被其他車占用的中途節點，起終點仍受站點進站檢查。
- `/api/entry` 成功回應包含 `path`、`route_token`；RCS 在同一鎖內原子預約整趟路徑的道路及節點，
  相反方向共用同一道路，不會分成兩條可同時通行的道路。路口也互斥，沒有先占一半路徑再等另一半的情形。
- 這是保守的整趟路徑預約；有衝突就留在出發點等待，不會自動搶路或強迫忙碌車倒車。
  尚無時間窗預約、路段逐一釋放、忙碌車互等解鎖或最優多車排程。
- 核准後車輛逐條道路移動，回報 `current_node`、`road_edge`、`route_path`、`route_token`。
  保留示意的取放貨階段；行駛時間依路徑長度而變，不再固定每張單 16 秒。
- RCS 收到車端在路徑終點的新車況（相同 token 且已離開道路）後，才釋放預約。
  任務 `routes` 保存每趟路徑的核准與釋放時間；舊任務不補造路徑。
- 半路暫停、離線或取消，不會把原道路視為已清空。RCS 重啟保留路徑預約，將原任務標為待確認，不重派。
- 取消後若模擬車仍占道路，可在「路徑與路段交管」對該車明確操作「模擬復歸至等待點」。
  POST `/api/roads/recover` 會直接設定模擬位置及解除預約；要求車已取消任務、回報送完、目標未占用。
  復歸不是行駛，也不是正式車端安全流程；正常搬運與自動讓位不使用此捷徑。

主頁地圖顯示真正的路網線段、單向箭頭及各車核准路徑，並可看到路段預約與等待的車號。
「目前追蹤任務的路徑」對應上方任務選擇，可追查取料、送貨及讓位的實際路徑。

驗證：停止本專案後執行 `python tests/navigation.py`，使用 `run/tests/` 中的獨立資料。
涵蓋單向最短路徑、交叉路口互斥、等待與接續、暫停保留預約、取消後人工模擬復歸、離線及重啟持久化。
測試與範例都不是實際 AGV 避碰認證。

## RCS 車況查詢的 API 可見性

API 分頁上方固定顯示三台 AGV 的最近 RCS GET /api/state 接收端紀錄，包括車號、正確連接埠與時間。
點選車卡可直接查看該次請求與 JSON 回應；按「看 RCS 查詢車況」會清除任務篩選並只列出 RCS→AGV 查詢。
這些查詢通常不帶 task_id，因此選定某張任務時不會出現在原本的任務封包列表。
RCS 約每 0.5 秒查詢；紀錄面板每 2 秒取樣。車況查詢與 AGV 主動任務回報／心跳是不同方向。

### 介接服務與車端的通訊邊界

介接服務只向 RCS 取得任務、車況與畫面快照，由 RCS 查詢 AGV。介接服務與車端畫面的 `/api/snapshot` 均由 RCS 彙整；早期介接服務 `/api/vehicle` 也改由 RCS 的 `/api/vehicles` 取得 CT-SIM-01。RCS 離線時回傳錯誤，不繞過 RCS 直查車端。

### 2026-11-03 通訊邊界整理（取代較早的畫面彙整說明）

規格以 [API_STANDARD.md](API_STANDARD.md) 為準。介接服務僅轉送外部任務相關操作，已移除介接服務模擬移車與復歸；介接服務轉送保留 HTTP 狀態碼。AGV 快照僅讀本車，RCS 不為畫面反查介接服務或透過 HTTP 查自己。API 清單新增用途分類，注意事項頁列出角色、資料規則及正式版待辦。新增 WCS／ECS 後為 69 種定義、99 個服務入口。

### 點到點移動 MOVE

介接服務下單表單可選搬運或點到點移動。`POST :8210/api/tasks` 增加可選 `kind`：`TRANSPORT`（預設）／`MOVE`。例如 `{"request_id":"MOVE-001","kind":"MOVE","requested_vehicle":"CT-SIM-01","from":"A","to":"B"}`。車先前往起點再移至終點，不進行取放料；沿用通行許可、道路預約、自動讓位與回報。相同 request_id 不可改用另一種任務類型。`tests/move.py` 使用獨立測試資料驗證路徑、讓位、取消與重啟保存。


### WCS／RCS／ECS 第一階段（2026-11-03）

啟動腳本現在啟動七個程序：介接服務8210、RCS8211、AGV8212–8214、WCS8215、ECS8216。介接服務預設「整張搬運作業」使用 /api/jobs，點到點使用 /api/tasks MOVE；舊 TRANSPORT 保留相容。WCS 依設備條件協調 MOVE 與取放料握手，同一張作業鎖定同一台車到完成。新資料分開存在 data/wcs.json、data/ecs.json，舊 rcs.json 不重設。

WCS / ECS 各有獨立管理頁。ECS 可切換模擬設備的有料、可收料、故障與自動完成。來源尚未有料不派車，到站不等於取放料完成，必須等 ECS 握手。API 傳輸頁會合併 WCS/ECS 診斷紀錄，暫停畫面仍可使用。

WCS 重啟的非取消中已指派作業、ECS 重啟的未完成交接標記待確認並保留用車；取消中的作業繼續查證，不能直接恢復以免重做動作。已補整張作業取消；設備等待逾時與人工對帳／模擬復歸畫面已實作；車端真實取放料與 PLC 接線仍未實作。暫停 WCS 只阻止下一步，不停止已派出的車或設備操作。詳見 API_STANDARD.md 及注意事項。

tests/workflow.py 使用隔離資料驗證七服務、設備等待、同車鎖定、命令去重、暫停、WCS/ECS 重啟與防重做；既有 tests/integration.py、tests/move.py 保留舊任務與 MOVE 回歸驗證。

整張搬運作業目前只接受 A、B、C、WIP、CUT、CNC、OVEN、PACK 八個設備交接站。充電站、待命區、空閒區及避讓點仍可用 MOVE 抵達，但不冒充有取放握手的機台。

對外畫面名稱為「外部介接入口」，服務名稱 integration-service（原稱中央）。網址仍為 :8210；既有 API、role: central 與 --role central 保留相容，不改歷史資料。程式入口處理函式改稱 integration_handler，啟動紀錄與新日誌使用 integration-service 名稱。此服務目前接收、轉交、查詢，完整 API Gateway 的認證／限流仍未實作。


### 整張作業取消（第二階段第一項）

- 外部介接入口／RCS 管理頁代理 `POST /api/jobs/{job_id}/cancel` 到 WCS；可帶 `reason`。首次202表示已持久保存取消要求，不表示取消完成。相同作業重送只查回同一取消結果，完成作業不能用取消撤銷。
- WCS 停止正常流程推進，即使原作業已暫停也會處理取消。取消時若已有 HTTP 指令在途，仍須查證；RCS `/api/job-cancel` 與 ECS `/api/interactions/cancel-job` 保存屏障，阻止後續同作業動作。
- RCS 逐一取消該作業子任務；交付中等接單結果確認。已接受的讓位動作先完成到等待點，不在半路直接解除。ECS 只停止未完成的模擬交接；完成與結果不明的紀錄不被改寫。
- 取消最終可能為 CANCELED（已確認取消）、INTERRUPTED（待人工確認、保留資源）或 COMPLETED／TOO_LATE（放料已完成，未撤銷結果）。已取料、車在半路、道路仍有預約、回報不明等情況不釋放用車。
- 取消期間保存要求／期限／階段、證據與時間點。預設60秒確認期限，可用 WCS_CANCEL_TIMEOUT_MS 設1000～300000毫秒；此為取消確認期限，不是一般業務步驟逾時。逾時轉待人工確認，不當作停止成功。
- WCS 重啟的取消中作業會繼續確認，不恢復正常作業步驟。RCS 保存取消屏障及成功解除的紀錄；ECS 保存取消屏障與模擬操作結果，避免重啟後重做。未知或已載貨情況仍需後續人工對帳功能，不提供強制清空保留。
- GUI 的「取消整張作業」與原有「取消 RCS 子任務」不同；後者不代表整張作業已取消。API 紀錄增加 job_id／command_id 供關聯檢查。設備取消仍是本機模擬，不是實際 PLC 安全停止。


## 人工確認與模擬復歸

WCS `/api/jobs/{job_id}/recover` 僅處理「已提出取消且 INTERRUPTED」的作業。重啟中斷須先取消；正常執行、已完成或已取消的作業不能藉此復歸。內部 WCS 操作頁提供處理人、說明、等待點及五項確認；外部介接入口8210回403。來源標頭仍不是正式身份認證，正式部署需加入權限與操作員登入。

首次202表示確認已保存，狀態RECOVERING。WCS先確認ECS交接停止並保存獨立人工對帳，再請RCS核對在線、無任務、回報已送完及目標無占用／預約，直接設定模擬位置至P1/P2/P3/I1/I2；核對成功後一次保存RCS復歸收據及解除作業用車、原作業道路預約。這不是實際行駛或真車復歸協定；貨物清空是人工聲明，非感測器驗證。

成功後作業CANCELED、cancel_phase=MANUALLY_RESOLVED、recovery.state=DONE。保留原步驟、任務狀態、已完成／不確定交接及所有事件，另記人工處理貨物、處理人、時間、位置和各服務收據；不重跑原搬運。ECS故障／有料信號不自動改寫。車輛原暫停狀態不自動解除。

60秒仍未確認時回INTERRUPTED、recovery.state=BLOCKED，保留尚未解除資源。相同確認內容與request_id可重試；不同內容回409，避免部分成功後更改位置。WCS重啟續查收據；RCS收據必須先於車況檢查去重，已解除車輛即使正在執行新單也不再次設定位置。設備等待逾時已有本機版本；真車感測及人工身份權限仍待實作。


## 設備等待期限與異常處理

內部WCS/ECS頁提供「設備等待期限與異常處理」。兩服務各有GET/POST `/api/policy`；外部介接入口不轉送此管理API。單位毫秒，設定範圍1000～86400000（畫面以秒輸入），持久保存，WCS套用新作業、ECS套用新交接。各作業／交接保留建立時的政策快照，變更不縮短既有期限。舊資料無期限時從首次監控起初始化，不以過去建立時間誤判。

預設WCS來源／目的設備各300秒、ECS結果確認120秒；ECS等待允許30秒、允許後等待完成60秒。採實際時間，包含流程暫停、離線與重啟時間。暫停仍不停止已發起的設備交接；WCS持續唯讀監控已發起交接與等待期限，但不發起下一步。移動與派車交通逾時屬RCS，未在此新增。

ECS交接逾時為TIMED_OUT，設備故障為FAILED，包含alarm{code,owner,station,command_id,occurred_at,message}。異常碼ECS_ALLOW_TIMEOUT／ECS_COMPLETION_TIMEOUT／EQUIPMENT_FAULT；ECS重啟未完成交接為INTERRUPTED／ECS_RESTART。截止後信號才恢復不改回成功；相同command_id回原結果，不重置計時。未對帳站點不接受新交接。

WCS來源或目的等待逾時為SOURCE_WAIT_TIMEOUT／DESTINATION_WAIT_TIMEOUT；未能取得設備完成結果（含通訊中斷）為ECS_RESPONSE_TIMEOUT。WCS收到ECS異常保留其owner和code，作業轉INTERRUPTED，保存一次ALARM事件、等待期限與原因。已收到完成結果不倒寫成逾時；未知載貨／交接結果仍需人工處理。故障信號清除不自動恢復作業。

處理方式：符合條件時由WCS人工確認後接續；否則取消整張作業，協調停止後人工確認與模擬復歸。保留已完成／逾時／不確定的原交接，另存對帳收據；已對帳的異常不再阻擋設備接新作業。貨物、用車、道路仍按原取消／復歸規則確認，不因超時直接釋放。實車／PLC故障碼、硬體安全停止、操作權限、設備斷線心跳及自動重試策略尚待實作。


## 確認異常後繼續原作業

內部WCS POST `/api/jobs/{job_id}/continue` 接受request_id、operator、note、equipment_ready、vehicle_stopped、cargo_confirmed與interaction_result。外部8210不開放；RCS內部管理頁可轉送。首次202為RESUMING，表示已保存確認，未代表已恢復。重送同一request_id及內容回原結果，不重做；不同內容409。保存人工接續陣列continuations（原步驟、原異常、處理人、時間、證據），成功清除目前alarm但保留原ALARM事件。

僅支援未取消、INTERRUPTED的WAIT_SOURCE／WAIT_DEST／PICK／DROP。WAIT_SOURCE確認尚未取料、來源有料且無故障後重新計時；WAIT_DEST確認貨物仍在原車、目的可收料後重新計時。PICK／DROP必須填interaction_result=COMPLETED，明確人工確認實際已完成，才分別接WAIT_DEST／RELEASE，不重新執行本次交接。未完成或不明仍用取消與結案，不提供重做按鈕。

WCS以內部 `/api/job-continue-check` 請RCS核對：原作業無取消屏障、原車保留一致、子任務均已完成、車在線、原站點、無路段中斷、未暫停、空閒、回報送完、無道路／站點預約。接續不改位置、不換車、不卸貨、不解除保留。TO_SOURCE／TO_DEST等移動中斷不在本階段範圍；已取消／正在取消及結案復歸中的作業不可接續。

ECS內部 `/api/interactions/confirm-result` 保存獨立confirmed_results：核對job／command／vehicle／station／action一致、交接已完成或已停止（TIMED_OUT／FAILED／INTERRUPTED）、無故障及無其他交接。原操作status與時間不改寫；模擬有料信號依人工完成的PICK=false／DROP=true更新。已確認操作不再阻擋設備，取消判斷也納入人工完成證據，避免重複取放料或誤判載貨。這是本機人工聲明，不是實車感測驗證。

RESUMING預設60秒核對；未通過保持保留，逾時INTERRUPTED且attempt.state=BLOCKED，可原內容重試或取消。WCS重啟繼續核對、ECS確認收據持久去重。成功沿用原作業的政策快照重算下一等待期限。取消優先於接續：並行取消要求合併後不恢復正常流程。操作員登入／授權與實車載貨、定位、交接結果驗證仍待對接。


## 待人工確認處理清單與提醒

WCS頁新增「待人工確認」分頁、跨頁提醒橫幅；介接入口／RCS操作頁的WCS作業區有清單連結。可按提醒程度篩選、搜尋作業／車號／設備／原因，依等待最久排序。顯示原異常、首次待確認時間、等待多久、原車、載貨紀錄及RCS實際保留的用車、道路路徑與站點。關聯設備不等於已被占用；尚未精算被阻擋的其他任務數。

GET WCS `/api/attention`回傳checked_at、policy、summary、items、storage_error、rcs_error。WCS儲存attention_since，進入INTERRUPTED時設定；重啟／重試不歸零，取消／接續／復歸核對期間仍列出。成功接續或完成／取消結案後移出，原異常／確認歷史保留。再次發生新異常開始新的等待時間。舊資料首次載入依alarm.occurred_at或updated_at補入時間。

POST WCS `/api/attention/policy`接受warning_ms、critical_ms；1000≤黃色<紅色≤86400000。預設300000／900000毫秒（畫面5／15分鐘），立即影響目前與之後清單，持久保存，與業務步驟逾時政策分開。未達門檻WAITING、達黃色WARNING、達紅色CRITICAL；包含核對與離線期間的實際時間。

RCS資源只核對本作業及其關聯讓位任務；已經屬於其他作業的車輛預約不歸到舊作業。RCS離線、資料格式不完整或儲存異常時resources.known=false，畫面標示無法確認，不顯示假零值；WCS連線中斷保留上次畫面並顯示未更新。狀態為本次查詢快照，不是真車安全驗證。

清單按鈕沿用確認後接續、取消及人工結案API，不另行繞過核對。提醒和政策設定不操作AGV、不自動釋放保留、不發送外部通知。外部介接8210不開放提醒管理API。指定人員通知、已讀／接手／值班升級、通知歷史及真車感測／正式權限仍待實作。
